# TickDeck PRD 对抗式产品评审

- 评审视角：挑剔的开源产品负责人、投资者与潜在核心贡献者
- 评审对象：`prd.md`、`addendum.md`、`.memlog.md`
- 评审日期：2026-08-27
- 结论：**NO-GO（当前不宜进入完整 v1.0 投资与 Epic 承诺）**

PRD 对功能、安全、数据溯源和运行约束写得相当完整，但“完整”正在掩盖两个尚未跨过的产品门槛：第一，当前没有能让真实目标用户完成 A/港股研究的已授权数据路径，v1.0 门槛却允许只用演示数据通过；第二，差异化只是“未发现完全同构竞品”，并没有证据证明目标用户愿意承担自托管、数据授权和模型配置成本，或全工具 Agent 能带来足以替换现有工具链的增量价值。若直接把 83 个 FR 拆成 Epic，项目很可能以高昂成本造出一个功能齐全、但真实数据不可用、用户切换理由未成立的产品。

| 严重度 | 数量 | Gate 含义 |
|---|---:|---|

| Medium | 4 | 在 alpha 验收设计前解决 |
| Low | 1 | 文案与口径清理 |
| **合计** | **13** |  |

## Critical

### C-01：v1.0 可以在没有任何真实 A/港股数据连接器的情况下“验收通过”

**位置：** `prd.md:16-20`、`prd.md:104-111`、`prd.md:127-135`、`prd.md:334`、`prd.md:348`、`prd.md:374-375`、`prd.md:385-392`；`addendum.md:14-16`、`addendum.md:44-52`。

**攻击：** 产品承诺是 A/港股专业研究闭环，但当前没有商用授权，FR 只要求连接器框架、能力声明和演示数据；SM-01 明确用演示数据验收，NFR-025 也只保障演示模式。OQ-03 没有截止到某个发布 Gate，也未规定 v1.0 至少要有一个经真实授权联调的生产级数据路径。按当前文本，项目完全可能用 mock/合成数据、四个“仅骨架”连接器和可工作的 UI/Agent 达到大多数要求，同时对真实用户没有可用研究价值。这不是普通集成风险，而是产品是否存在的前置条件。

**可执行修复：**

1. 增加不可豁免的 `v1.0 live-data invariant`：至少一个获授权且通过真实联调的 A 股数据路径和一个港股数据路径（可由同一或不同连接器提供）。
2. 定义每个一等市场的最小生产能力档案，例如证券主数据、交易日历、日线/约定盘中周期、复权与公司行动、筛选所需基础字段；基本面、公告、新闻若是 v1 必备，也要规定最低覆盖与新鲜度，而不是仅写“以能力矩阵为准”。
3. 用真实授权环境跑 UJ-1、UJ-2 和模拟组合验收；演示数据只承担开发、安装和安全回归，不得替代产品价值验收。
4. 将 OQ-03 升级为架构决策前的 spike Gate 和公开 beta 前的 phase blocker；若指定日期前无法获得合法接入，则收窄 v1 承诺或提供经许可的文件/数据库导入路径，而不是继续堆上层功能。

### C-02：产品 thesis 未验证，却被“无未确认产品假设”错误地宣布为已解决

**位置：** `prd.md:16-24`、`prd.md:36`、`prd.md:344-359`、`prd.md:394-396`；`addendum.md:81-104`；`.memlog.md` 中“当前不主张额外差异化价值”以及 D5/D11 的决策记录。

**攻击：** 竞品资料只证明各产品具有或不具有哪些功能；“尚未发现完全同构产品”最多说明方案组合有差异，不能证明目标用户有未满足需求、愿意自托管并购买/配置数据和模型、也不能证明 Agent 的价值大于迁移成本。addendum 已诚实写明这是“差异化假设，不是市场需求已验证”，PRD 却在假设索引中宣称“无未确认的产品假设”。SM-01 至 SM-07 都是在完整产品或大量能力做出后测试，SM-08 又是发布后才验证采用；项目没有便宜证伪、停止或收窄的 Gate。

**可执行修复：**

1. 在 PRD 中恢复显式假设台账，至少包括：目标用户当前工作流痛点、BYO 数据/模型与自托管接受度、Agent 的增量决策价值、A/港股聚焦带来的切换动机、贡献者供给。
2. 在八组能力全面建设前运行 2–3 个廉价验证：真实任务访谈与现有工作流计时、用可点击原型或 concierge Agent 执行选股任务、用窄化策略原型完成“策略契约→生成→回测解释”。
3. 增加比较性指标与 kill criteria，例如 Agent 相对用户现有工具链使完成时间/漏错率改善达到约定门槛，且第二次任务仍愿意复用；若未达到，则优先收窄为 Agent-first 研究层或连接器/策略开发平台，而非继续补齐 TradingView 功能清单。
4. 把 SM-08 的核心采用验证前移至重大投入之前，发布后 90 天指标只验证留存与扩散。

## High

### H-01：八组能力是并列清单，不是可发布的依赖顺序

**位置：** `prd.md:100-111`、`prd.md:123-266`、`prd.md:370-381`。

**攻击：** “0.x 可渐进交付”没有回答先交付什么闭环、每一阶段验证哪项风险、什么结果决定继续。八组能力横跨高性能图表、资讯授权、任务调度、不可信代码隔离、回测、模拟撮合、Agent 审批、模型兼容和四类扩展；它们彼此强耦合，不能靠“每个预发布版本公开能力缺口”化解永久未发布风险。当前文本会让 Epic 拆分按模块横向铺开，直到很晚才发现垂直闭环不可用。

**可执行修复：** 增加依赖排序与阶段 Gate，至少形成：M0 数据/模型/工具契约与演示运行；M1 真实数据上的手动研究 + Agent 选股闭环；M2 TypeScript 策略 + 回测闭环；M3 提醒 + 模拟组合；M4 安全、兼容、双语和贡献者硬化。每一阶段写清必需 FR、明确不做项、可体验的端到端任务、证据门槛和停止条件。允许顺序调整，但必须坚持“垂直价值切片先于八个横向模块齐头并进”。

### H-02：成功指标验证“能完成”，没有验证 Agent 是核心竞争力或值得切换

**位置：** `prd.md:18`、`prd.md:54-60`、`prd.md:344-368`。

**攻击：** UJ 完成率、语法编译率、工具结果一致性和安全不越权都是质量底线，不是竞争优势。没有 Agent-on 与 Agent-off、现有脚本/券商终端/TradingView 工作流的比较；没有决策时间、人工修正次数、关键条件漏失、证据核查成本、二次复用率或用户愿意迁移的衡量。即使所有 SM 通过，也只能证明产品能工作，不能证明 Agent 是“核心竞争力”。

**可执行修复：** 对 UJ-1、UJ-2增加对照任务与增量指标：总决策时间、人工步骤/修正次数、漏错和错误接受率、证据回溯成功率、第二次同类任务复用率、相对现有工具的偏好与切换意愿。预先规定 minimum detectable improvement 和不达标时的收窄/重做条件，不以主观满意度代替行为证据。

### H-03：Agent 基准允许“语义错误但成功运行”的策略和选股通过

**位置：** `prd.md:218-242`、`prd.md:348-354`；`addendum.md:156-160`。

**攻击：** SM-04 的“条件解析正确率 90%”没有定义字段级、任务级还是人工评分，且候选与确定性引擎一致只证明引擎忠实执行了已解析条件；解析错了仍可 100% 一致。SM-05 只要求“可编译、可回测”，语义颠倒、错误仓位、错误时间口径或遗漏风险条件的策略也能通过。FR-066/067 以一次结构化工具调用测试授予“完整 Agent 模式”，没有证明模型能在多步、暂停恢复、失败重试和诱导内容下守住契约。

**可执行修复：** 建立版本化 benchmark spec：自然语言条件到规范化 AST 的严格匹配、候选集 precision/recall、策略契约字段覆盖、已知策略行为/交易序列对照、市场规则陷阱、前视/泄漏检测 recall 与 false-positive、工具注入和恢复测试。按具体模型版本、上下文上限和工具集发布兼容档案；“完整 Agent 模式”应通过代表性多步任务套件，而不只是结构化调用握手。

### H-04：“比肩 TradingView”的验收语义仍然可以被功能占位符满足

**位置：** `prd.md:16-24`、`prd.md:109-111`、`prd.md:137-188`、`prd.md:385-386`；`addendum.md:83-104`。

**攻击：** PRD 将“比肩”改写为核心任务不跳出，但没有列出哪些具体任务、质量深度和规模才算替代。`常用价格图形`、`核心绘图工具`、`常用指标`、`关键指标`、`公告与新闻`都未冻结目录、字段覆盖、交互精度和数据质量。一个极简 K 线、四个指标、几个筛选字段和新闻标题列表即可字面满足 FR，却无法支撑公开宣称。OQ-02 甚至把关键目录留到 Epic 前，说明范围还没达到可估算状态。

**可执行修复：** 在承诺使用“比肩”前建立任务级 parity rubric：固定 8–12 个目标用户高频任务，分别写最低能力目录、数据覆盖、交互/性能、保存与复现、错误/缺失行为，以及与基准产品的验收方式。把 OQ-02 在 Epic 拆分前关闭，并为基本面/资讯/提醒补同样的 minimum viable depth；否则将愿景措辞降为“面向 TradingView 类工作流”。

### H-05：首要用户与实际采用成本存在未处理的资格矛盾

**位置：** `prd.md:20`、`prd.md:34-45`、`prd.md:64-74`、`prd.md:236-254`；`addendum.md:18-25`。

**攻击：** 首要用户被描述为“不想自行拼接基础设施”的进阶投资者，但可用产品要求有人部署 Fastify Web 服务、配置反向代理、获取并合法使用数据授权、配置模型和费用、维护备份与升级。UJ-1 直接从“已配置数据源和模型”开始，跳过最可能阻断采用的过程；UJ-3 又把它交给另一个角色，但个人自托管场景中通常是同一个人。目标群到底是“有商用终端/API 权益且能自托管的技术型投资者”，还是普通进阶投资者，关系到市场大小、UX 和安装承诺。

**可执行修复：** 收窄并量化首发 ICP：已有何种数据权益、部署技能、当前工具链、每周任务频率和可接受配置时间。明确投资者与部署者是同人还是可分工，并为两种情况各写首次真实研究旅程。若首发必须是高度技术型用户，公开承认这个 beachhead；若要覆盖更广用户，则必须提供合法、低摩擦的真实数据接入和一键式本地部署，而不能只靠文档。

### H-06：公开开源发布目标缺少可持续维护与治理承诺

**位置：** `prd.md:42-45`、`prd.md:256-266`、`prd.md:324-325`、`prd.md:356-359`、`prd.md:390`。

**攻击：** 五名贡献者、三次合并不是开源生态可持续性的证据。项目承诺四类稳定扩展、四浏览器三代、双语、安全响应、数据厂商变更适配和不可信代码沙箱，这会形成长期维护义务；PRD 没有 maintainer capacity、决策权、贡献审核 SLA、发布节奏、兼容支持窗口、贡献者信任模型或 bus-factor 门槛。OQ-06 只覆盖安全响应，不能回答“谁长期维护这个免费产品”。核心贡献者看到的是广泛责任，而不是可拥有的模块边界。

**可执行修复：** 增加 launch-readiness/governance 章节：maintainer 与模块 ownership、决策/RFC 流程、发布和 LTS/兼容策略、贡献审查时限、第三方扩展责任边界、漏洞披露与密钥轮换、最低 bus factor。把 SM-09 改成“外部贡献者首次贡献时长、二次贡献率、review turnaround、至少两个关键模块存在非创始人 owner”等健康指标。

## Medium

### M-01：Agent 的“可审计”界面可能把内部执行噪声强加给投资者

**位置：** `prd.md:36`、`prd.md:220-232`、`prd.md:366`。

**攻击：** FR-054 要持续展示计划、阶段、工具名、参数、来源、耗时、费用、状态和失败原因，但没有规定默认信息层级。对量化开发者这很有价值，对首要用户可能成为调试控制台；SM-C04 只测确认疲劳，不测工具轨迹带来的理解负担。核心体验可能“透明但不可读”。

**可执行修复：** 要求结果优先的渐进披露：默认显示结论边界、证据和待确认动作；工具级轨迹可展开，错误时自动露出相关步骤。增加理解度、找到来源耗时和信息过载任务测试，并区分投资者/开发者视图偏好。

### M-02：发布后采用指标证据强度不足，且与无遥测立场没有闭环

**位置：** `prd.md:325`、`prd.md:356-359`。

**攻击：** “30 名自愿反馈用户在三个日期完成旅程”高度受自选择偏差影响，也没有定义用户唯一性、如何证明完成、核心旅程是哪一条、三个日期间隔或留存窗口。默认无遥测是合理隐私选择，但当前没有替代取证机制，指标易被 anecdote 满足。

**可执行修复：** 定义隐私友好的自愿 evidence pack：本地生成、用户主动导出、去标识化的旅程完成摘要；规定 cohort、日期间隔、有效运行清单和去重规则。同时补定性访谈和留存/复用证据，明确它是样本观察而不是整体用户率。

### M-03：部分成功指标与需求的映射有明显缺口

**位置：** `prd.md:348-354`。

**攻击：** SM-01 实际要求“打开图表并完成 Agent 查询”，却声称验证 FR-005、FR-065 至 FR-076，没有引用图表 FR-008 至 FR-014 或 Agent FR-052 至 FR-064。SM-05 引用了全部 FR-029 至 FR-043，但“可编译、可回测”并不验收图表信号、版本化、偏差检测或敏感性质量。这会给测试与发布团队制造虚假的覆盖感。

**可执行修复：** 删除宽泛的“验证 FR 范围”，改成每个 SM 的具体测试断言与覆盖清单；未被任何发布测试覆盖的 FR 单独暴露。至少补图表、产物版本、偏差陷阱、长任务取消/恢复和回放验证。

### M-04：性能门槛未绑定真实用户数据形态，可能优化错误问题

**位置：** `prd.md:297-306`、`prd.md:389`。

**攻击：** 10,000 标的、30 个“已准备字段”和本地缓存让筛选 p95 很容易与真实厂商 API、字段稀疏、跨市场日历、增量更新和基本面报告期处理脱钩；10,000 根 K 线也未说明周期、指标窗格数量或浏览器尺寸。数字看似精确，但无法证明真实 UJ-1/UJ-2 体验。

**可执行修复：** 为每个 NFR 固定公开基准数据包、数据形态、缓存冷热、指标/叠加数量、浏览器分辨率和并发任务；同时记录端到端用户等待时间并拆分供应商、队列、计算、渲染。alpha 可以调整阈值，但不能只测理想化 prepared-data microbenchmark。

## Low

### L-01：“完全免费”容易与强依赖的第三方费用形成不必要的信任落差

**位置：** `prd.md:16`、`prd.md:20`、`prd.md:291-293`；`addendum.md:24-25`。

**攻击：** 文档后文已经说明数据、模型和基础设施可能收费，但愿景首句的“完全免费”会被外部传播截取为总拥有成本为零。在没有内置真实数据或模型的情况下，这尤其容易引发反噬。

**可执行修复：** 对外统一改为“TickDeck 软件本身完全免费、Apache-2.0 开源；第三方数据、模型与基础设施由用户自行采购并付费”，并在安装前显示最低可用成本路径和演示模式与真实研究模式的区别。

## 建议的放行条件

只有在以下四项完成后，才建议把 PRD 作为完整 v1.0 的 Epic 输入：

1. 明确至少一个真实 A 股和一个真实港股授权数据路径及最小能力档案，完成可行性 spike。
2. 通过低成本原型验证“Agent 相对现有工具链的增量价值”和目标 ICP 对 BYO/自托管成本的接受度，并写下 kill criteria。
3. 把八组能力重排为有依赖、有退出指标的垂直发布切片。
4. 修订 Agent benchmark，使它测语义正确性、市场规则和多步安全，而不仅是能调用工具、能编译、能跑回测。

在此之前，可以批准 M0/M1 的探索与可行性工作，但不应把“免费开源 TradingView + 全工具 Agent”当作已经成立的产品 thesis，也不应承诺 83 个 FR 的完整实施范围。
