## Remaining High

### H-R01：S3 的 Go 门依赖尚未在 S4 实现的提醒与模拟组合，Gate 图形成死锁

**位置：** `prd.md:141-167`、`prd.md:466-470`。

**问题：** S3 只实现 TypeScript 策略、回测、偏差和语义基准，却要求 SM-11 通过；SM-11 又要求 §6.4 十项任务全部通过，而任务 7 是提醒，任务 10 是模拟组合订单，这两项明确到 S4 才实现。于是 S3 在进入 S4 前无法 Go，S4 又按原则不能在 S3 Go 前进入承诺。`S5` 才是完整 Parity Rubric 的合理位置。

**修复：** 把 SM-11 拆成 `SM-11a 策略/图表 parity` 与 `SM-11b 提醒/模拟 parity`，S3 只要求前者，S4 要求后者，S5 再要求完整十项；同时逐行校验每个 SM 只引用当前或此前切片已实现的能力。

### H-R02：“先便宜证伪”仍被完整沙箱和双市场生产数据集成前置

**位置：** `prd.md:37`、`prd.md:158-167`、`prd.md:510-513`；`addendum.md:148-166`。

**问题：** S0 在任何用户价值实验前要求沙箱、恢复、安全共同运行时全部过基准；S1 又要求 A 股与港股两条路径完整达到包含五年/分钟线、财务、资讯、许可与一致性测试的 v1.0 画像。Agent 选股 thesis 本身不需要 TypeScript 沙箱、模拟副作用授权，也未必需要同时完成两个市场的生产级连接器。当前顺序可能先投入最昂贵、最不确定的工程与商务工作，之后才发现用户不需要 Agent，违背“先验证再扩张”。

**修复：** 在 S0 前增加限时 S-1 discovery/spike，或把 S0/S1 分成“最小只读选股实验地基”和“v1.0 生产资格”；SM-00 可先在一条合法真实数据路径上验证方向，A+港双路径、完整沙箱和全套恢复仍作为 S1/S3/v1.0 不可豁免 Gate，而不是 thesis 实验的前置成本。

### H-R03：任意 BYO 模型仍可凭一次结构化工具测试获得完整 Agent 权限

**位置：** `prd.md:289-296`、`prd.md:338`、`prd.md:461-464`；`addendum.md:168-174`。

**问题：** FR-066/067 和 addendum 仍规定“通过结构化工具调用测试”即可进入完整 Agent 模式；新增 FR-094 与 SM-04/05 是产品发布 benchmark，没有明确绑定每个实际模型配置档案、模型版本、提示模板与工具集。一个弱本地模型可以通过握手后在真实工作区执行多步任务，语义质量远低于发布时所测模型。R1/R2 能防部分副作用，却不能防错误筛选、错误策略解释和高可信错误结论。

**修复：** 为模型档案增加分层运行时资格：简单结构化测试只解锁低风险单步工具；完整 Agent 必须以该模型版本、提示/策略版本和当前工具集通过缩减但代表性的多步语义与注入基准，并在任一组成变化后失效重测；UI 应明确区分“技术兼容”与“经任务验证”。

### H-R04：A-02 的关闭条件没有测量真实数据/模型配置成本

**位置：** `prd.md:43-45, 73-83, 452-460, 517-523`。

**问题：** A-02 声称验证用户愿意承担数据、模型和自托管配置成本，但 UJ-1 从“已配置”开始，SM-01 只要求在演示数据上 15 分钟完成首次受限查询，SM-00 则比较配置后的真实任务表现。两项都可能在研究团队代装环境后通过，不能证明目标用户能或愿意完成最关键的采用障碍。A-02 的关闭条件因此与假设不一致。

**修复：** 增加真实 onboarding 指标：从空白发行物到连接既有合法数据服务与模型端点的成功率、无协助完成率、p50/p95 时间、凭据/授权理解错误和放弃率；分别记录“投资者本人部署”与“部署者代配”两种路径，并据此决定 ICP 或部署形态。

## Medium

### M-R02：SM-01 的 FR 覆盖声明仍然不准确

**位置：** `prd.md:458`。

测试动作是“打开图表并完成 Agent 查询”，但覆盖只写 FR-005、FR-065–076，没有包含图表 FR-008–014 与 Agent FR-052–064；应改成测试断言级覆盖表，不再用宽范围宣称替代实际验证。

### M-R03：Agent 执行轨迹仍未规定渐进披露

**位置：** `prd.md:43, 280-288, 482`。

首要用户仍可能被计划、工具名、参数、耗时、费用和失败细节淹没；SM-C04 只管确认疲劳，应要求结果优先、证据次之、工具轨迹可展开，并加入理解度/信息负担测试。

### M-R04：SM-08 仍无法形成可靠采用证据

**位置：** `prd.md:472-475`。

“30 名自愿反馈用户在三个日期完成核心旅程”仍没有去重、日期间隔、完成证据或隐私友好的采集机制；应定义本地生成且由用户主动提交的去标识化 evidence pack，并明确这只是观察样本而非总体留存率。

### M-R05：精确性能数字仍未绑定可复现实验负载

**位置：** `prd.md:393-402, 509`。

10,000 根 K 线和 10,000×30 prepared fields 未指定图表尺寸、叠加指标、缓存冷热、字段稀疏或跨市场更新方式；应固定公开基准包和端到端延迟拆分，避免通过理想化 microbenchmark。

## Low

### L-R01：“完全免费”仍可能被理解为总拥有成本为零

**位置：** `prd.md:16, 20, 374-376`。

对外口径应统一为“TickDeck 软件本身完全免费并按 Apache-2.0 开源；数据、模型与基础设施可能产生第三方费用”，避免愿景首句被脱离上下文传播。

## Gate 处置建议

本次复审不再要求重开原两项 Critical：真实数据和产品 thesis 已成为诚实、不可静默跳过的假设与 Gate。下一步只需先修正四项 High，而不是继续扩写更多安全或功能要求：

1. 修复 S3/S4 的 Gate 死锁；
2. 把最小 thesis 实验前移，避免先造完整沙箱和双市场生产栈；
3. 将语义资格绑定到每个实际模型档案；
4. 为 A-02 增加真实 onboarding 验证。

完成后，产品评审可给 **CONDITIONAL GO**：允许按切片与 Stop/Narrow 条件推进，但仍不能把待验证假设表述成已成立的市场事实。
