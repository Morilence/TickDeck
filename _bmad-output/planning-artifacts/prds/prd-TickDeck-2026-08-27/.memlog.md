topic: TickDeck 产品需求文档
updated: 2026-08-27T16:55

- (decision) 产品暂定名为 TickDeck，定位为专注 A 股与港股的开源研究和模拟交易工具，面向进阶个人投资者与量化开发者。
- (decision) v1 目标覆盖行情图表、自选与筛选、基本面与资讯、提醒、指标与策略、回测、模拟组合的研究闭环，明确不支持实盘下单。
- (decision) 内置 Agent 可使用产品内全部可用工具和方法；查询计算自动执行，持久化修改、高成本调用和模拟交易按风险分级确认。
- (decision) 市场能力随用户配置的数据源而定，重点适配 Wind、Choice、iFinD 等权威厂商并允许扩展其他数据源；当前没有商用数据授权可供联调。
- (decision) Agent 模型支持商业模型、OpenAI-compatible 服务与本地模型，由部署者配置。
- (decision) 产品支持在产品内编写 TypeScript 指标和策略，并通过沙箱运行。
- (decision) 产品采用 B/S 架构，支持本地运行和远端自托管；不建设完整用户体系，远端认证由反向代理负责。
- (decision) 技术栈指定为 TypeScript、Fastify、React、shadcn/ui Base UI、Tailwind CSS、Mastra，开源协议为 Apache-2.0。
- (event) 用户确认没有其他输入材料；后续 Discovery 以当前产品描述和实时竞品研究为输入。
- (decision) TickDeck 以正式面向外部发布、吸引真实用户与开源贡献者为目标，因此 PRD 按 launch 级严谨度编制并执行显式评审门禁。
- (decision) 用户选择 Coaching path；PRD 将通过逐节引导、确认后成文，而不是批量假设生成。
- (decision) Coaching path 采用 Vision + Features 入口，先澄清产品承诺、差异化和能力边界，再定义功能要求。
- (event) Concern scan 识别到数据授权与能力差异、行情和计算可信度、Agent 权限与成本、不可信代码隔离、模拟交易审计、自托管认证、公共接口兼容、开源贡献体验及 v1 范围密度。
- (decision) 当前不主张额外差异化价值；核心愿景是提供完全开源、完全不收费、专业能力可比肩 TradingView 的产品。
- (decision) 产品愿景分为两层：基本工具原则上覆盖 TradingView 的核心专业能力；可调用产品全部研究与模拟交易能力的强大内置 Agent 是核心竞争力。
- (decision) Agent 的两项代表性核心任务是：按自然语言条件筛选股票；根据自然语言要求编写交易策略并完成验证。
- (override) 用户授权由助手提出具体产品决策、用户逐项拍板；保留 Coaching path 的逐节确认，不直接批量定稿。
- (decision) D1 批准：Agent 选股任务必须生成可审计、可复跑的研究结果；确定性工具执行筛选，披露数据能力与不确定性，允许零候选，持久化动作需确认，最终决策归用户。
- (decision) D2 批准：Agent 策略任务需形成策略契约、可编辑 TypeScript 代码、沙箱检查、含真实执行假设的回测报告、偏差和过拟合检查及可复现运行清单；高成本、持久化与模拟交易动作需确认。
- (decision) D3 批准：TickDeck 不充当数据供应商，不内置或转售商用数据；提供明确标识的合法演示数据；连接器以运行时能力矩阵和验证成熟度驱动功能启用、降级与拒绝，并披露来源、时间和完整性。
- (decision) D4 批准：v1 一等支持沪深北 A 股和港交所股票，指数仅作观察与基准；TradingView 对标范围限于 A/港股股票研究，不承诺其他资产或实盘，并正确处理两地市场规则。
- (decision) D5 批准：以核心任务无需跳出 TickDeck 作为 TradingView 功能等价标准；v1.0 必须具备图表、自选筛选、基本面资讯、提醒、指标策略创作、回测、模拟组合和全工具 Agent 八组能力，0.x 可渐进交付。
- (decision) D6 批准：进阶个人投资者为首要用户，量化开发者为第二用户，自托管部署者与开源贡献者为关键使能角色；默认界面与 Agent 优先服务投资者，编程和扩展保持一等能力。
- (decision) D7 批准：以研究选股、策略创作验证、自托管运维、无商用授权的开源贡献四条具名端到端旅程覆盖核心价值、开发者价值、可部署性和开源增长，并包含降级与失败恢复。
- (decision) D8 批准：Agent 采用 R0 自动、R1 范围授权、R2 逐次确认、R3 禁止四级风险模型；确认绑定准确参数和状态，模拟订单严格确认，执行全程可审计且重试幂等。
- (decision) D9 批准：所有用户或 Agent 生成的 TypeScript 均按不可信代码处理；沙箱默认无网络、文件和宿主权限，采用窄化 API、固定依赖、资源配额、故障隔离、可复现清单及持续逃逸测试，副作用仍受 Agent 风险策略约束。
- (decision) D10 批准：完整应用以 Apache-2.0 免费发布，无付费功能锁和强制云服务；v1 仅本地与远端自托管，一实例一受信工作区，无账号/RBAC/多租户；第三方成本透明、密钥服务端隔离、支持备份迁移且默认无遥测。
- (decision) D11 批准：采用 v1.0 安装、用户旅程、Agent 基准、安全与沙箱发布门槛，并在发布后 90 天验证外部采用和贡献；保留零编造、零越权、零预算超支等反指标，alpha 后调整需留存基线和理由。
- (decision) D12 批准：模型配置支持多档案、商业与 OpenAI-compatible/本地兼容服务；通过能力测试后分为完整 Agent 或仅总结模式，支持预算、成本披露和单次切换，不做自动跨服务回退或多模型编排，确定性数据与计算不交给模型。
- (decision) D13 批准：确立参考环境下的启动、图表和筛选性能，可取消长任务、确定性复现、幂等恢复、备份迁移、脱敏可观测性、WCAG 2.2 AA、桌面浏览器支持及中英双语等跨模块 NFR；供应商延迟必须独立披露。
- (decision) D14 批准：v1 稳定扩展面限于数据连接器、模型适配器、Agent 工具和通知渠道，脚本使用独立沙箱 API；扩展契约类型化、版本化且具契约测试，第三方输入边界校验，v1 不承诺插件市场、脚本社区或外部公共 REST API。
