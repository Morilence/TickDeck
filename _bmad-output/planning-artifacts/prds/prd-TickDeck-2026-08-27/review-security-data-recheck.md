# TickDeck PRD 安全与数据治理复审

## Gate verdict

**BLOCK — 0 Critical，1 High。**

最新 PRD 已把原评审的大部分方向性要求转成 FR-084–100、NFR-031–040 和 SM-10–15 的发布合同。原 2 个 Critical 中，DataUsePolicy 已关闭；应用访问边界对非回环部署已关闭，但本地回环模式仍没有同等级的受保护会话与浏览器来源验收，因此原 SEC-AUTH-002 仅部分关闭并降级为 1 个 High。该项补齐后，可进入 **PASS WITH MEDIUM/LOW FOLLOW-UPS**。

## Remaining High

### RECHECK-H-001：本地回环模式没有浏览器来源与状态修改安全门禁

- **位置：** FR-071（第 305 行）、FR-089–090（第 333–334 行）、§8.5（第 378–382 行）、NFR-033（第 441 行）、SM-14（第 469 行）、addendum“应用层访问边界”（第 202–212 行）。
- **证据：** FR-089、NFR-033 和 addendum 都把明确的受保护会话、CSRF 与旁路测试限定在“非回环部署”。本地模式只承诺监听 loopback；这不能自动阻止用户访问恶意网页后，由浏览器向 `localhost` 发起跨站请求、跨站 WebSocket、DNS rebinding 或利用错误 Host/Origin 触发 Agent 与持久化副作用。
- **具体修复：** 把 FR-089、FR-090 与 NFR-033 的浏览器来源要求扩展到**所有浏览器可访问模式，包括 loopback**；本地模式至少要求实例级受保护会话或等价不可猜测 capability、严格 Host/Origin、CSRF、跨站 WebSocket 和 DNS rebinding 防护。SM-14 增加从恶意公网页面攻击本地参考实例的自动化测试，成功状态修改、Agent 执行、外部调用和模拟订单均必须为 0。
- **关闭条件：** 修订后的 PRD 明确覆盖 loopback，并将上述本地攻击场景列入不可绕过的 v1.0 Gate。

## Medium follow-ups

### M-01：秘密存储与全路径泄漏测试仍未明确

FR-096 已覆盖生命周期和备份，但未规定服务端最小文件权限/秘密后端边界，也未要求以 canary secret 扫描浏览器响应、Agent 上下文、日志、审计、诊断、错误栈和导出；应在 S0 安全基准中补充。

### M-02：受信扩展的权限清单尚不等于技术最小权限

FR-097 要求记录“秘密访问”和展示实际权限，但未明确扩展只能取得获批 secret references，或当扩展拥有完整服务进程权限时必须以阻断性文案披露；架构必须选择强制最小权限或诚实的全权限信任模型，并纳入 SM-15。

### M-03：追加式审计 schema 仍缺少最低字段和篡改/删除语义

FR-093 已解决副作用一致性，但 PRD 未列出事件 ID/序列、可信时间、来源主体、Agent run、工具/策略版本、批准 ID、幂等键、前后状态和费用等最低字段，也未规定审计导出/清理自身留痕；应在架构合同中补齐。

### M-04：提示注入没有固定攻击语料 Gate

服务端再授权已使提示注入不能直接越权，但当前 SM-06/SM-14 没有明确覆盖公告、新闻、连接器错误、工具输出、模型输出、多轮持久上下文和既存 R1 授权中的中英双语间接注入；应加入固定回归语料。

### M-05：模拟交易历史更正语义仍未闭合

FR-048、FR-093 与 NFR-036 处理幂等和故障一致性，但组合重置、公司行动修订、乱序/重复成交和事后数据回补是追加更正还是覆盖历史仍不明确；应定义稳定事件 ID、账本世代和 `as-of` 版本。

### M-06：连接器成熟度仍混合技术状态和部署实例授权状态

FR-003 的“试用验证 / 正式授权验证 / 允许再分发”仍把实现成熟度、特定账号 entitlement 与使用场景放在一条轴上。DataUsePolicy 已显著降低风险，但 UI 和契约仍应分成 `implementationMaturity`、`entitlementState` 与具体用途策略。

### M-07：隐私与数据流清单仍未成为交付物

FR-087 的资产清单面向许可数据生命周期，不等于完整隐私/数据流说明；自选、策略、组合、提示、代理身份头和日志进入哪些本地存储或第三方模型/通知服务仍应在公开 alpha 前形成数据流清单。

### M-08：安全报告渠道仍晚于公开 alpha

FR-099、NFR-040 和 addendum 第 221–231 行把公开渠道与响应演练设在 v1.0 RC 前，但公开 0.x alpha 已运行不可信脚本、扩展并保存真实凭据；最小 `SECURITY.md`、私密报告渠道和紧急禁用流程应前移到首个公开 alpha。

## Low follow-up

### L-01：“严重”“已知”和例外接受口径仍未统一

NFR-018 仍未指定漏洞数据源、直接/传递依赖范围、严重度算法、扫描新鲜度、误报证据、例外负责人和到期时间；在发布测试计划中补齐即可，沙箱逃逸与密钥泄漏不得作为普通例外放行。

## 通过条件摘要

本轮修订已经足以关闭 DataUsePolicy、统一出站、Agent 不可重放授权、沙箱固定合规套件、秘密备份冲突、受信扩展供应链、审计副作用一致性、授权到期清理和提示注入越权这九类原 Critical/High 问题。唯一仍阻止安全 Gate 的问题是：**相同的应用层浏览器防护必须覆盖 loopback 本地模式，并有攻击本地实例的自动化验收。**
