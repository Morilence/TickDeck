# TickDeck 产品需求文档

## 当前决策状态

- **允许进入：** S0-V 真实任务证伪、S0 架构设计、UX 探索及对应 Epic 设计。
- **尚未获准：** 完整 v1.0 并行实施；必须依次通过 §6.6 的 S0-V 至 S5 Gate。
- **核心待证：** A-01、A-02、A-05，即 Agent 增量价值、自托管配置接受度和任务级 Parity。A-03 已由“合法免费数据源默认优先”的产品决策替代；A-04 与外部贡献增长指标 SM-09 已撤销。真实数据资格仍由 OQ-03、SM-10 和阶段 Gate 控制。

## 0. 文档目的

本文档定义 TickDeck v1.0 的目标产品承诺、目标用户、用户旅程、功能要求、非功能要求、数据与安全边界、验证门槛和非目标。它面向产品、UX、架构、开发、测试、安全评审和开源贡献者。功能要求使用全局稳定编号 FR-001 至 FR-100；后续 UX、架构、Epic 与 Story 必须引用这些编号。本文档不是完整 v1.0 实施的无条件开工许可：各垂直切片必须按 §6.6 的顺序通过 Go/Stop 门。具体技术选型、厂商接入现实、竞品证据与实现边界见同目录 addendum.md。

## 1. 产品愿景

TickDeck 是一款专注 A 股和港股的开源、完全免费的专业研究与模拟交易工具。它保留 TradingView 类产品的专业工具属性，去除用户体系、社交、课程和实盘券商连接，让进阶个人投资者在一个自托管工作台中完成行情观察、选股、研究、提醒、指标与策略创作、回测和模拟组合管理。

TickDeck 的基础门槛是在明确的 A/港股股票范围内，让核心研究任务不必跳出产品；核心竞争力是内置 Agent。Agent 与用户共用同一套产品工具，能够把自然语言意图转成可审计、可复跑的研究和策略验证过程，而不是只提供聊天或生成无法验证的结论。

TickDeck 不提供市场数据、模型托管或投资建议。部署者自带合法的数据与模型接口，产品根据实际能力启用、降级或拒绝任务。所有最终投资判断属于用户；v1.0 不支持实盘下单。

### 1.1 待验证的产品 thesis

[ASSUMPTION A-01] 当前产品 thesis 是：对已有 A/港股研究经验、合法数据访问和自托管能力的用户，把 TradingView 类研究工作台、TypeScript 策略验证和全工具 Agent 合并到一个由用户掌控数据与模型的开源环境中，能够显著减少跨工具编排时间和研究漏错，并产生二次复用。

这是一项待证假设，不是已验证的市场事实。竞品调研只证明现有方案的能力分散，不能证明目标用户愿意迁移、承担配置成本或持续使用 TickDeck。完整 v1.0 建设必须先通过真实任务对照实验；失败时按 §6.6 收窄为更薄的工具或停止全工具 Agent thesis。

## 2. 产品原则

1. **工具闭环优先。** “可比肩”指核心任务无需跳出 TickDeck，不指逐个复制 TradingView 的全部功能。
2. **证据优先。** 数据、计算、回测与模拟结果必须可追溯；数据不足时允许零候选或拒绝执行。
3. **确定性计算。** 数值筛选、指标、回测和组合核算由确定性工具完成，模型负责规划、调用和解释。
4. **能力随源而定。** 功能承诺绑定当前连接器的能力矩阵，不把厂商名称当作可用性证明。
5. **风险与成本可见。** Agent 自动化程度由工具风险、参数、成本和当前状态共同决定。
6. **默认本地掌控。** 数据、模型、研究产物和运行环境由部署者控制，不依赖官方云服务。
7. **开源可贡献。** 没有商用数据授权的贡献者仍能用演示数据开发、测试和提交贡献。
8. **先验证再扩张。** 只为通过当前垂直切片所需的能力实施；后续能力在前一 Go 门通过前不得变成并行承诺。

## 3. 目标用户

### 3.1 首要用户

具备市场知识和一定技术理解的进阶个人投资者。他们愿意配置数据源和模型，希望获得专业工具与自动化研究能力，但不想自行拼接图表、数据、脚本、回测和 Agent 基础设施。

[ASSUMPTION A-02] 首轮 alpha ICP 进一步限定为：每周至少完成两次 A/港股研究任务；已经合法使用至少一种真实 A 股或港股数据服务；能够自行配置 Docker 或等价本地服务与模型端点；当前依赖 TradingView、券商终端、表格或脚本中的至少两种工具；愿意用同一真实任务分别执行现有流程和 TickDeck 流程，并在两周内复用第二次。alpha 样本整体必须同时覆盖 A 股和港股数据权益。

### 3.2 第二用户

量化开发者。他们需要可编程指标与策略、确定性回测、模拟组合、稳定扩展契约和可复现运行；TickDeck 不以替代机构级量化生产或实盘执行平台为目标。

### 3.3 关键使能角色

- 自托管部署者：负责安装、反向代理认证、数据与模型配置、备份、升级和故障诊断。
- 开源贡献者：开发连接器、Agent 工具、通知渠道、指标、策略或产品功能。产品保留可贡献路径，但不以外部贡献人数证明产品成功。

### 3.4 v1.0 非用户

- 需要一键开户、实盘下单、跟单或经纪服务的交易者。
- 依赖社交观点、直播、课程或公开脚本社区的新手用户。
- 需要机构级多租户、RBAC、审计归属或生产交易 SLA 的团队。
- 主要研究美股、期货、期权、外汇、加密资产、债券或基金的用户。

### 3.5 核心 Jobs To Be Done

- 当我有一个选股想法时，帮我把条件变成可验证的筛选，说明候选为何入选、哪些证据不足，并让我继续研究和跟踪。
- 当我有一个策略想法时，帮我形成可读的 TypeScript 策略，安全运行并解释其回测可信度，而不是只给出漂亮收益。
- 当我研究某只股票时，把图表、基本面、资讯、提醒、脚本和组合上下文放在同一工作台中。
- 当我自托管产品时，让我清楚知道当前数据、模型和扩展到底支持什么、花费多少、是否健康。
- 当我贡献开源代码时，让我无需商用授权也能验证契约、安全边界和完整开发流程。

## 4. 核心用户旅程

### UJ-1：周岚完成一次可审计的选股研究

周岚是一名进阶个人投资者，已在受信工作区中配置数据源和模型。她向 Agent 描述选股条件。Agent 先确认关键口径并检查数据能力，再用确定性工具执行筛选，展示候选、命中证据、风险、不确定项、数据来源和时间。周岚进入候选标的工作台，查看图表、基本面、公告与新闻，保存筛选器和自选，创建提醒，最后确认是否加入模拟组合。若数据不足，Agent 明确降级、拒绝或返回零候选，不猜测或补全结果。

### UJ-2：陈宇把策略想法变成可信验证

陈宇是一名量化开发者。他描述策略意图后，Agent 形成一份明确市场、周期、信号、仓位、风控、基准和执行假设的策略契约，生成 TypeScript 草稿并在沙箱中编译与试运行。陈宇查看、修改代码，运行回测、样本外和敏感性验证，检查交易明细、回撤、费用、偏差与复现清单。通过验证后，他确认保存策略并选择是否将其信号接入模拟组合。失败时，系统保留诊断并支持修改后复跑。

### UJ-3：赵琪安全部署并维护一个受信工作区

赵琪可以启动桌面客户端、本地 B/S 实例或远端自托管实例。桌面客户端与本地 B/S 默认仅连接回环地址；远端实例由她通过 HTTPS 反向代理保护。三种入口使用同一工作区、能力清单和 Gate。她配置数据源和模型凭据，运行连接与能力测试，看到实际支持范围、配额、费用和健康状态。升级或故障后，她可以导出脱敏诊断、备份并恢复配置与研究产物。她理解同一实例没有个人账号与 RBAC，只向彼此信任的人开放。

### UJ-4：林舟在没有商用数据时完成开源贡献

林舟是一名外部贡献者。他使用演示数据和兼容测试模型启动完整开发环境，基于脚手架新增指标、Agent 工具、通知渠道或数据连接器，通过类型检查、契约测试、沙箱测试和文档检查验证贡献。专有 SDK、真实数据和密钥不进入仓库。服务端扩展的受信权限与沙箱脚本的受限权限在贡献说明中清楚区分。

## 5. 词汇表

- **受信工作区**：一套 TickDeck 部署实例及其共享数据、配置和产物。v1.0 不在工作区内划分用户身份或权限。
- **标的**：可由数据源描述的市场对象。v1.0 一等支持沪深北 A 股和港交所股票；指数仅作观察与基准。
- **数据连接器**：把第三方或本地市场数据能力映射为 TickDeck 统一能力的受信服务端扩展。
- **能力矩阵**：连接器在运行时声明的市场、标的、数据类型、时效、深度、配额、健康状态和许可用途。
- **数据溯源信息**：随结果保存或展示的数据源、数据时间、获取时间、时区、币种、复权口径、完整性和新鲜度。
- **演示数据**：合成或获准再分发、明确标记为非当前行情的数据，用于开发、测试和产品演示。
- **研究产物**：可保存和复跑的筛选器、报告、图表布局、提醒、脚本、回测或其他研究输出。
- **策略契约**：策略运行前明确的市场、标的范围、周期、信号、仓位、风控、基准和执行假设。
- **沙箱脚本**：用户或 Agent 编写、按不可信代码运行的 TypeScript 指标或策略。
- **运行清单**：复现一次计算所需的源码哈希、参数、数据、引擎、编译器、运行时、依赖和成本模型版本记录。
- **回测**：在历史数据和明确成交模型上执行策略的确定性模拟，不代表未来或真实可成交结果。
- **模拟组合**：持有虚拟现金、持仓、订单和成交的研究组合，不连接真实券商账户。
- **Agent 工具**：注册到 TickDeck、具有类型化输入输出、能力条件、风险等级和成本属性的产品方法。
- **Agent 运行**：Agent 为一个用户目标进行规划、工具调用、暂停、恢复和产物生成的可审计过程。
- **风险等级**：Agent 工具按 R0 自动、R1 范围授权、R2 逐次确认、R3 禁止划分的执行策略。
- **模型配置档案**：一个模型服务的连接、能力、费用和运行参数集合。
- **受信扩展**：由部署者主动安装、在服务端权限边界内运行的代码；它不等同于沙箱脚本。
- **参考能力画像**：v1.0 真实 A/港股数据路径必须达到的供应商中立最低数据、时效、历史、许可和可靠性要求。
- **数据使用策略**：由连接器授权记录、部署使用范围、数据类别和目标动作编译出的默认拒绝执行策略。
- **出站策略**：控制模型、Webhook 和自定义端点可接收的数据类别、最小载荷、目的地址、凭据和预算的服务端策略。
- **Parity Rubric**：以高频任务、数据深度、交互质量、结果可复现和无需外部工具为维度的 TradingView 对标验收量表。
- **规范化条件树**：把自然语言筛选条件转成可审核、可执行、具有明确空值和时间语义的结构化表达。

## 6. v1.0 范围与发布定义

### 6.1 一等市场范围

- 沪、深、北交易所 A 股。
- 港交所上市股票。
- 主要市场和行业指数仅用于行情观察、相对比较和回测基准。
- 行情粒度、历史深度、盘口、基本面和资讯以能力矩阵为准。

### 6.2 v1.0 必备能力组

v1.0 必须同时达到图表工作台、自选与筛选、基本面与资讯、提醒、指标与策略、回测、模拟组合、内置 Agent 八组能力的验收标准。0.x alpha/beta 可以逐步交付，但不得把不完整闭环宣传为 v1.0。

### 6.3 明确非目标

- 实盘下单、券商连接、跟单、自动交易或投资顾问服务。
- ETF、场外基金、债券、期货、期权、外汇、加密资产、美股及其他全球资产的一等支持。
- 个人账号、组织、RBAC、多租户、陌生用户共享或官方托管 SaaS。
- 社交、直播、课程、公开脚本社区、在线插件市场或远程一键安装扩展。
- TickDeck 内置、转售或绕过授权获取 Wind、Choice、iFinD 等商用数据。
- 自动多模型路由、多 Agent 编排、模型托管或本地模型下载管理。
- v1.0 受支持的外部公共 REST API。

### 6.4 真实数据参考能力画像

合法免费数据源是 TickDeck 的默认数据选项；商用或付费数据源仅作为部署者主动配置的可选替代，不是发布前提。默认不等于自动可信：免费与付费真实路径都必须先通过同一许可、能力、溯源和健康校验，才能注册相应能力。v1.0 必须至少具有一条经真实授权验证的 A 股数据路径和一条经真实授权验证的港股数据路径；可以由同一或不同连接器提供。两条路径都必须：

- 覆盖标的主数据、交易日历、交易状态、币种和公司行动；
- 提供不少于 5 年日线 OHLCV，以及不少于最近 250 个交易日的 1、5、15、30、60 分钟 K 线；若合同只允许比上述要求更粗的时间粒度，不能通过 v1.0 Parity Rubric 验收；
- 提供当前报价或明确的延迟报价，并可验证数据时间、获取时间、时区和新鲜度；
- 提供筛选所需的公司基础资料、主要财务报表和关键指标；
- 提供公告或新闻元数据；全文仅在许可允许时展示和发送给模型；
- 对本地展示、允许期限内缓存、派生指标、回测、备份、模型发送和导出分别记录许可状态；
- 通过字段、限频、断线、重连、复权、公司行动和历史/实时一致性契约测试。

盘口深度、Tick、逐笔和 Level-2 不属于参考能力画像，可作为连接器增强能力。默认免费路径若不能满足字段、时效、历史、稳定性或许可要求，相关能力必须显式降级，且不能通过完整 v1.0 真实数据 Gate。演示数据只能通过开发与 alpha 界面验收，不能替代免费或付费真实数据路径。

### 6.5 任务级 TradingView Parity Rubric

[ASSUMPTION A-05] v1.0 必须在两条真实数据路径上完成以下高频任务，并达到对应 FR/NFR，不以页面或按钮存在代替：

1. 搜索并打开标的，切换 1、5、15、30、60 分钟及日、周、月周期。
2. 使用蜡烛、OHLC、线、面积和 Heikin-Ashi 图形，检查未完成 K 线与数据溯源信息。
3. 添加、配置和移除内置指标；最小目录为 SMA、EMA、WMA、Bollinger Bands、MACD、RSI、Stochastic、ATR、ADX、CCI、OBV、VWAP。
4. 使用趋势线、水平线、垂直线、射线、矩形、Fibonacci 回撤、文本、价格区间、日期区间和测量工具并保存布局。
5. 比较股票与指数、检查基本面和时点资讯。
6. 构建、保存、复跑筛选器并进入候选研究。
7. 创建和验证价格、指标、筛选与策略提醒。
8. 编写、运行和可视化 TypeScript 指标。
9. 编写策略、完成回测、查看偏差和复现清单。
10. 在明确确认后向模拟组合提交订单并检查组合影响。

每项任务必须记录完成率、外部工具跳出、数据缺口、p95 交互性能、可访问性和复现结果。目录变更必须版本化并通过 Reviewer Gate。

策略偏差检查矩阵见 §7.7。

### 6.6 依赖有序的 0.x 决策门

| 切片 | 仅实现的垂直范围 | Go 门 | Stop / Narrow |
|---|---|---|---|
| S0-V 廉价 thesis 证伪 | 一条合法真实数据路径、只读筛选工具、受限 R0 Agent、固定任务对照；不建设脚本沙箱、提醒或组合 | SM-00 通过 | 未改善时间、漏错和复用则停止全工具 Agent thesis，不进入平台化建设 |
| S0 契约与安全地基 | 演示数据、统一工具/数据契约、运行清单、风险策略、沙箱、单工作区访问边界及只承载当前阶段能力的 B/S/桌面双入口壳 | 契约、权限、双入口等价性、沙箱和恢复基准通过 | 无法形成安全且可复现的共同运行时则停止全工具 Agent |
| S1 真实数据薄闭环 | 一条 A 股和一条港股真实路径，完成“打开图表→筛选→证据结果” | §6.4 参考能力画像及许可记录通过 | 任一市场无法获得合法可用路径则不得承诺 A/港股 v1.0 |
| S2 Agent 选股产品化 | 在双市场真实路径上产品化规范化条件树、证据产物、保存与复跑 | SM-02、SM-04、SM-10 通过 | 语义或真实数据资格不稳定则维持实验，不扩张策略能力 |
| S3 策略验证价值 | TypeScript 策略、回测、偏差矩阵、语义基准 | SM-03、SM-05、SM-07、SM-11 通过 | 只能生成可编译代码但不能通过行为基准则停止自动策略生成 |
| S4 提醒与模拟闭环 | 提醒、组合、模拟订单、审计、数据生命周期 | SM-06、SM-12 至 SM-14、SM-16 通过 | 无法证明副作用一致性和市场规则正确则不启用 Agent 模拟交易 |
| S5 v1.0 发布硬化 | 八组能力、Parity Rubric、双语、可访问性、备份、扩展与治理 | 全部 v1.0 SM/NFR 通过 | 未通过项保持 beta，不以 v1.0 发布 |

## 7. 功能要求

### 7.1 市场数据、标的与能力治理

**描述：** 所有市场功能以当前数据连接器的真实能力为前提。用户和 Agent 看到同一能力矩阵和数据溯源信息。实现 UJ-1、UJ-2、UJ-3、UJ-4。

- **FR-001 配置数据连接器。** 部署者可以创建、测试、启用、停用和诊断多个数据连接器；凭据不得回显给浏览器或 Agent。
- **FR-002 声明能力矩阵。** 每个连接器必须声明市场、标的类型、实时或延时状态、K 线周期、历史起点、盘口深度、基本面、资讯、配额、健康状态和许可用途。
- **FR-003 标记连接器成熟度。** 系统必须区分仅骨架、试用验证、正式授权验证和允许再分发；未联调连接器不得显示为可用。
- **FR-004 附带数据溯源信息。** 图表、筛选、指标、回测、Agent 和模拟组合使用的数据必须可查看来源、时间、时区、币种、复权、完整性和新鲜度。
- **FR-005 提供演示数据。** 无论是否配置默认免费或可选商用真实数据，部署者和贡献者都能使用固定版本、固定种子的确定性合成数据完成核心界面、Agent、回测、模拟组合和扩展测试；数据必须明确标记 `demo/non-current`，不得打包第三方真实历史行情，也不得冒充默认免费真实路径或生产资格。
- **FR-006 显式降级。** 数据缺失、陈旧、超额、断连或不支持时，系统必须显示相应状态并降级、拒绝或返回零结果，不得静默补值或换源。
- **FR-007 处理 A/港股市场语义。** 相关功能必须识别交易日历、币种、复权、停牌、涨跌停、T+1、最小交易单位、费用和公司行动差异。

### 7.2 图表工作台

**描述：** 图表是用户研究的主工作台，与标的、筛选、基本面、资讯、脚本、提醒和 Agent 上下文相连。实现 UJ-1、UJ-2。

- **FR-008 搜索与切换标的。** 用户可以按代码、名称和市场搜索支持的股票与指数，并看到当前连接器支持状态。
- **FR-009 展示行情图形。** 用户可以查看 K 线和常用价格图形；可用周期和盘中深度必须服从能力矩阵。
- **FR-010 管理窗格与叠加。** 用户可以在主图或独立窗格添加价格比较、成交量、内置指标和沙箱指标。
- **FR-011 比较标的与基准。** 用户可以在统一时间和币种口径说明下比较多个股票或指数。
- **FR-012 检查单点数据。** 十字光标和数据检查器必须显示时间、OHLC、成交信息、指标值、数据状态和未完成 K 线状态。
- **FR-013 使用核心绘图工具。** 用户可以创建、编辑、隐藏和删除常用趋势、水平、区间和测量类绘图。
- **FR-014 保存研究布局。** 用户可以保存、复制、恢复和删除图表布局，并从 Agent 产物或其他研究模块打开关联布局。

### 7.3 自选与筛选

**描述：** 自选和筛选把市场范围缩小成可解释、可持续跟踪的研究集合。实现 UJ-1。

- **FR-015 管理自选列表。** 用户可以创建多个自选列表，增删和排序标的，并查看可配置行情与研究列。
- **FR-016 构建组合筛选。** 用户可以使用行情、技术、基本面、市场和连接器支持的字段，组合筛选条件、排序规则和排除项。
- **FR-017 保存并复跑筛选器。** 用户可以保存筛选定义、数据口径和排序，基于后续时点的数据复跑并比较结果变化。
- **FR-018 展示匹配证据。** 每个筛选结果必须展示命中条件、未满足或未知条件、关键数值、数据溯源信息和进入标的工作台的入口。
- **FR-019 支持零候选与受控导出。** 系统允许返回零候选；导出结果必须尊重数据许可和部署配置，不得默认开放批量再输出。

### 7.4 基本面、公司行动与资讯

**描述：** 用户在同一标的上下文中查看公司事实、财务表现、公司行动和时点相关资讯。实现 UJ-1。

- **FR-020 展示公司资料。** 用户可以查看由当前连接器提供的公司、行业、上市地和证券基础资料。
- **FR-021 展示财务与关键指标。** 用户可以按报告期查看财务报表和关键指标，系统必须区分原始字段与派生计算。
- **FR-022 展示公司行动。** 分红、送转、拆并股、停复牌和其他可用公司行动必须与图表、复权和模拟组合处理关联。
- **FR-023 聚合公告与新闻。** 用户可以按标的和时间查看连接器允许展示的公告与新闻，并进入对应图表时间点。
- **FR-024 处理缺失和许可限制。** 无权限、无全文、延时或仅有摘要时，系统必须明确标记，不得以模型补写原文。

### 7.5 提醒

**描述：** 提醒把研究条件转成持续监控，但不自动转化为实盘或模拟订单。实现 UJ-1、UJ-2。

- **FR-025 创建提醒。** 用户可以基于价格、指标、筛选条件或策略信号创建提醒，并设置标的范围、频率和有效期。
- **FR-026 管理提醒生命周期。** 用户可以查看、暂停、恢复、编辑、测试和删除提醒；编辑后必须保留版本和后续生效时间。
- **FR-027 发送通知。** v1.0 至少支持产品内通知和部署者配置的 Webhook；失败必须重试受控并可诊断。
- **FR-028 记录触发证据。** 每次触发必须保存条件、数据时间、计算版本、结果和通知状态；提醒本身不得提交模拟订单。

### 7.6 TypeScript 指标与策略

**描述：** 用户和 Agent 可以创作、诊断、运行和版本化沙箱脚本。指标用于计算与可视化，策略用于历史验证和模拟信号。实现 UJ-2、UJ-4。

- **FR-029 提供内置指标。** v1.0 提供覆盖趋势、动量、波动和成交量的常用指标，具体发布目录在 alpha 前冻结。
- **FR-030 提供 TypeScript 编辑体验。** 用户可以创建指标或策略，获得类型提示、格式化、错误定位、运行日志和只读运行上下文说明。
- **FR-031 暴露窄化脚本 API。** 沙箱脚本只能访问版本化、类型化的市场数据、指标和回测 API，不能直接访问服务端环境或存储。
- **FR-032 编译与试运行。** 系统必须在正式运行前完成编译、类型校验、能力校验和受限试运行，并把诊断关联到源码位置。
- **FR-033 强制资源与依赖限制。** 每次运行必须强制执行 CPU、内存、实际经过时间、输出、数据请求和并发配额；只允许使用版本锁定的内置 API 和明确列入允许范围的依赖。
- **FR-034 版本化脚本。** 保存或覆盖脚本时必须创建可追踪版本，记录作者来源为手动或 Agent、源码哈希、依赖和兼容范围。
- **FR-035 连接图表与信号。** 指标输出可视化到图表；策略信号可用于回测、提醒和经确认的模拟组合接入，但不能直接访问组合存储。

### 7.7 回测与策略验证

**描述：** 回测以可复现和真实性披露为中心，不以最高收益为成功标准。实现 UJ-2。

- **FR-036 建立策略契约。** 运行前必须明确市场、标的范围、周期、信号、仓位、风控、基准和执行假设；关键缺口阻止运行。
- **FR-037 冻结运行输入。** 每次回测必须生成运行清单，记录脚本、参数、数据范围、数据源、复权、引擎、费用和成交模型。
- **FR-038 模拟 A/港股执行。** 回测按适用市场处理交易日历、停牌、涨跌停、T+1、最小单位、手续费、税费、滑点和公司行动。
- **FR-039 输出完整报告。** 报告至少包含累计与年化收益、基准比较、最大回撤、波动、换手、交易明细、持仓变化和成本影响。
- **FR-040 检查常见偏差。** 系统必须检测或警示未来函数、前视偏差、未确认 K 线、数据泄漏、预热不足、幸存者偏差风险和明显参数过拟合。
- **FR-041 支持样本外与敏感性验证。** 用户可以划分样本内外，并对关键参数和成本假设执行受预算控制的敏感性分析。
- **FR-042 比较和复跑。** 用户可以比较多个回测运行，并从运行清单复跑；数据或版本不可得时必须说明不可完全复现。
- **FR-043 管理长时运行。** 回测和参数扫描必须显示进度、资源与成本，允许取消；超预算任务需遵循 Agent R2 或用户手动确认。

**策略偏差检查矩阵：**

| 偏差类别 | 默认结果 | 固定验收样例 |
|---|---|---|
| 未来数据、lookahead 或收盘后字段用于当期成交 | 阻止运行 | 未来价格、财报发布日期和错误时间对齐 fixture |
| 预热不足或未就绪指标参与信号 | 阻止运行 | 长周期指标短历史 fixture |
| 未确认 K 线或重绘信号 | 明示警告；策略契约禁止时阻止 | 实时 bar rollback/reload fixture |
| 复权、公司行动或交易日历不一致 | 阻止运行 | 分红、拆并股、停复牌 fixture |
| 幸存者偏差或 point-in-time 成分不可得 | 标记“无法判定”，不得宣称无偏 | 退市股和历史指数成分 fixture |
| 参数过拟合 | 警告并要求样本外/敏感性结果 | 多次参数搜索和 holdout fixture |
| 成交、滑点或费用假设缺失 | 阻止运行 | A/港股市价、限价、税费和最小单位 fixture |

### 7.8 模拟组合

**描述：** 模拟组合记录研究决策及其虚拟执行结果，不连接真实券商。实现 UJ-1、UJ-2。

- **FR-044 管理模拟组合。** 用户可以创建、重命名、归档、复制和重置多个模拟组合。
- **FR-045 管理多币种现金。** 组合可以记录人民币和港币现金、换汇假设、费用和总资产估值口径。
- **FR-046 提交模拟订单。** 用户可以提交受支持的市价单或限价单，也可以撤单或变更订单数量；Agent 提交每笔订单必须逐次确认。
- **FR-047 执行模拟撮合。** 撮合必须遵循当前数据粒度、市场时间、停牌、涨跌停、T+1、最小单位、费用和成交模型，并披露无法模拟的现实因素。
- **FR-048 记录订单与成交。** 订单、确认、拒绝、部分成交、撤单、费用和重试必须形成不可混淆的历史记录。
- **FR-049 核算持仓与绩效。** 组合必须确定性计算持仓、成本、已实现与未实现盈亏、现金、收益、回撤和币种影响。
- **FR-050 处理公司行动。** 分红、拆并股、送转和其他当前数据支持的公司行动必须以可审计方式影响现金与持仓。
- **FR-051 接入策略信号。** 用户可以把已保存策略接入模拟组合；启用、停用和每次 Agent 订单仍遵循风险确认，不构成无人值守自动交易。

### 7.9 内置 Agent 与风险治理

**描述：** Agent 是产品核心竞争力。它可以调用全部注册且当前可用的产品工具，但工具能力、数据能力、风险策略和用户预算共同限制实际执行。实现全部用户旅程。

- **FR-052 接受自然语言目标。** Agent 可以在图表、标的、筛选器、脚本、回测或组合上下文中接受任务，并明确当前使用的上下文范围。
- **FR-053 规划并调用产品工具。** Agent 可以组合调用查询、筛选、计算、图表、资讯、脚本、回测、提醒和模拟组合工具；不存在的能力不得由模型模拟。
- **FR-054 展示执行过程。** Agent 运行必须显示计划、当前阶段、工具名、参数摘要、来源、耗时、费用、状态和失败原因，并允许用户查看结果引用。
- **FR-055 完成可审计选股。** 对选股任务，Agent 必须结构化条件、检查能力、用确定性工具筛选、返回候选证据与不确定项、允许零候选，并把最终判断留给用户。
- **FR-056 完成可信策略验证。** 对策略任务，Agent 必须形成策略契约、生成可编辑 TypeScript、完成沙箱检查、运行受控回测、检查偏差并生成运行清单。
- **FR-057 执行 R0 自动操作。** 只读查询、确定性计算、预算内单次回测和临时草稿可自动执行，但必须留痕。
- **FR-058 执行 R1 范围授权。** 可撤销的低风险持久化操作需首次确认；授权必须限定工具、对象、范围和有效期。
- **FR-059 执行 R2 逐次确认。** 覆盖或删除产物、启用外部通知、高成本运行、向新外部服务发送数据、启用策略和模拟订单必须逐次展示影响并确认。
- **FR-060 阻止 R3 操作。** Agent 不得执行实盘下单、输出密钥、绕过数据许可、让沙箱脚本获得宿主权限或绕过风险策略。
- **FR-061 绑定确认状态。** 确认必须绑定精确工具、参数、运行 ID、数据或组合状态、工具版本和有效期；相关状态变化后必须重新确认。
- **FR-062 管理预算与取消。** 部署者和用户可以设置数据、模型、运行时间和并发预算；运行显示消耗并支持取消，未经批准不得超预算。
- **FR-063 暂停、恢复与幂等。** 等待确认、断线或故障后的 Agent 运行可以安全恢复；持久化工具和模拟订单不得因重试重复执行。
- **FR-064 生成可追溯产物。** Agent 结论必须引用工具结果与数据溯源信息，明确事实、计算、模型解释和未知项；模型不得把建议描述为确定收益或替用户拍板。

### 7.10 模型配置与能力分级

**描述：** TickDeck 支持商业、OpenAI-compatible 和本地兼容服务，但只有通过能力测试的模型可以操作工具。实现 UJ-1、UJ-2、UJ-3。

- **FR-065 管理模型配置档案。** 部署者可以配置提供商、Base URL、API Key、Model ID、请求头、超时、重试、上下文、价格和默认参数。
- **FR-066 测试模型能力。** 系统必须针对精确的模型版本、提示版本和工具集组合，验证连接、流式输出、结构化输出、工具调用、上下文长度、取消能力、多步语义正确性和提示注入抵抗，并保存最近测试结果。
- **FR-067 分级 Agent 模式。** 仅通过连接和结构化调用握手的模型最多使用无副作用的单步 R0 查询工具；只有通过代表性多步语义、风险与注入基准的精确模型/提示/工具集组合才能进入完整 Agent 模式。
- **FR-068 选择模型且不静默回退。** 用户可以设置默认模型并在任务前切换；系统不得未经确认自动切换到另一外部提供商。
- **FR-069 披露模型使用。** 每个 Agent 运行必须展示模型、上下文范围、Token 与费用估算；凭据和完整提示默认不得写入普通日志。

### 7.11 B/S、桌面客户端、自托管与持久化

**描述：** 完整产品同时提供 B/S 与桌面客户端；B/S 可本地运行或远端自托管，桌面客户端封装同一受保护本地实例。所有形态共享同一产品能力和权威状态，不依赖 TickDeck 官方账户或云服务。实现 UJ-3。

- **FR-070 提供完整 B/S 与桌面发行物。** Apache-2.0 发行必须提供 B/S 入口和桌面客户端，两者复用同一图表、Agent、回测、模拟组合、工作区数据与 Capability/Gate 合同，不得建立第二套桌面业务实现，也不使用付费功能锁、许可证服务器或强制官方云登录。
- **FR-071 支持桌面、本地 B/S 与远端 B/S 模式。** 桌面客户端封装受保护的本地回环实例；本地 B/S 默认只监听回环地址；远端 B/S 提供反向代理、HTTPS 和认证配置指南，但不内置完整用户体系。三种入口不得产生能力、数据语义或授权差异。
- **FR-072 明示单工作区边界。** 产品必须说明所有通过代理进入实例的人共享同一权限和数据，不提供用户归属、RBAC 或多租户隔离。
- **FR-073 持久化核心产物。** 配置、自选、布局、筛选器、提醒、脚本、回测、模拟组合和审计记录必须持久保存并具有一致标识。
- **FR-074 备份、恢复与迁移。** 部署者可以备份和恢复完整工作区；升级前可检查兼容性，迁移失败不得破坏现有可恢复数据。
- **FR-075 保护秘密。** 数据与模型凭据只保存在服务端秘密存储，不进入浏览器、Agent 上下文、普通日志、导出或模拟记录。
- **FR-076 提供健康与诊断。** 部署者可以查看连接器、模型、沙箱、任务队列、通知和存储健康状态，并导出脱敏诊断包。

### 7.12 开源扩展与兼容性

**描述：** v1.0 只承诺少而稳定的扩展面，避免把内部实现无意变成永久公共接口。实现 UJ-4。

- **FR-077 支持四类受信扩展。** v1.0 正式支持数据连接器、模型提供商适配器、Agent 工具和通知渠道扩展。
- **FR-078 提供类型化扩展契约。** 每个扩展必须声明标识、版本、兼容范围、能力、权限、配置结构、输入输出和统一错误语义。
- **FR-079 验证外部边界。** 第三方配置、响应和内容必须经过结构与内容校验；资讯或工具结果中的指令性文本不得改变 Agent 权限或系统行为。
- **FR-080 提供贡献脚手架。** 项目必须提供演示实现、生成模板、契约测试和无商用密钥的验证路径。
- **FR-081 区分脚本与受信扩展。** 产品和文档必须明确沙箱脚本受限运行，而服务端扩展是部署者主动安装并承担权限风险的受信代码。
- **FR-082 版本化与废弃。** v1.0 后公共扩展契约遵循语义化版本，优先采用向后兼容的增量变更；废弃能力至少跨一个次版本提供警告和迁移说明，只维护一个当前主版本。
- **FR-083 限制公共表面。** v1.0 不提供在线插件市场、公共脚本社区、远程一键安装或受支持的外部 REST API；应用内部接口不得宣传为公共契约。

### 7.13 发布资格、安全策略与项目治理

**描述：** 以下要求把数据授权、应用访问、Agent 授权、语义正确性、供应链和发布切片从原则变成可执行 Gate。实现全部用户旅程。

- **FR-084 实施参考能力画像。** 系统必须以机器可读契约验证 §6.4 的真实 A 股和港股数据路径；演示数据不能满足生产资格。
- **FR-085 阻止无真实数据发布。** v1.0 发布检查必须确认至少一条 A 股和一条港股路径处于正式授权验证状态，并保存授权用途、验证证据和到期时间。
- **FR-086 执行数据使用策略。** 服务端必须从连接器授权、部署使用范围、数据类别和目标动作编译默认拒绝的数据使用策略，统一裁决缓存、派生、模型发送、导出、通知、备份和清理。
- **FR-087 管理数据生命周期。** 系统必须维护原始缓存、派生数据、索引、研究产物和备份的数据资产清单；授权到期或撤销时执行清理或标记不可复现，并保留不含受限数据的审计证据。
- **FR-088 执行统一出站策略。** 模型、Webhook 和自定义端点调用必须经过目的地址允许列表、数据分类与最小化、凭据隔离、预算和重定向检查，并阻止服务器端请求伪造（SSRF）、DNS 重绑定（DNS rebinding）和跨主机凭据转发。
- **FR-089 建立应用层受保护会话。** 本地回环和远端部署都必须建立实例级受保护会话并防护 CSRF；代理身份可用于审计，但不形成 v1.0 用户/RBAC。
- **FR-090 验证浏览器、桌面 WebView、代理与网络边界。** 所有部署模式必须校验 Host、Origin 和 WebSocket 握手并防护 DNS rebinding；桌面 WebView 不得绕过应用会话或获得独立业务授权路径；远端模式还必须配置可信代理来源、校验转发头，并提供上游端口旁路检测或启动阻断。
- **FR-091 统一计算最终风险。** 最终风险等级由服务端策略引擎依据工具、参数、数据类别、目的端、成本和状态计算；扩展或模型只能提高，不能降低风险。
- **FR-092 使用不可重放授权。** R1/R2 授权必须绑定受保护会话或可信代理主体、工具和参数哈希、状态版本、一次性随机数（nonce）、有效期和使用次数。
- **FR-093 保证审计与副作用一致。** 批准、状态修改、模拟订单和审计记录必须通过事务发件箱（transaction outbox）或等价机制形成可恢复的一致结果；审计记录采用追加式数据结构（schema）。
- **FR-094 验证 Agent 语义。** 选股任务必须生成可审核的规范化条件树并以 oracle 数据计算 precision/recall；策略任务必须通过信号、持仓、市场规则陷阱和多步工具行为基准，编译成功不足以通过。
- **FR-095 执行沙箱合规套件。** 支持平台必须运行固定版本的逃逸、宿主对象、依赖投毒、网络/文件访问、无限循环、内存和输出耗尽测试；资源配置档案和测试证据随发布保存。
- **FR-096 管理秘密生命周期。** 所有凭据使用秘密引用（secret reference），支持创建、轮换、撤销和失效诊断；默认备份排除秘密，可选秘密备份必须独立加密并在恢复时重新确认。
- **FR-097 治理受信扩展供应链。** 安装与升级必须记录来源、哈希、锁定版本、软件物料清单（SBOM）、权限差异和秘密访问；支持禁用、撤回和回滚，官方扩展必须经过代码所有者审查。
- **FR-098 执行 Parity Rubric。** v1.0 发布必须在真实 A/港股路径上完成 §6.5 的版本化任务量表，不能以静态页面、占位数据或单元测试替代端到端验收。
- **FR-099 发布开源治理规则。** v1.0 RC 前必须公开项目维护者、CODEOWNERS、RFC 与发布流程、支持窗口、贡献首响目标和安全报告/响应时限。
- **FR-100 强制切片 Gate。** 构建计划、版本说明和发布检查必须引用 §6.6 当前切片；前一切片未 Go 时，后续能力只能实验，不能进入 v1.0 承诺。

## 8. 数据治理、安全与成本护栏

### 8.1 数据授权与使用

- TickDeck 不内置或转售商用数据，不绕过账号、设备、IP、并发、配额或使用范围限制。
- 单人自用、受信小范围共享、公网展示、API 再输出、缓存、全文资讯和发送给外部模型是不同使用场景；只有连接器配置和合同明确允许的场景才能启用。
- 厂商 SDK、二进制、字段字典和示例数据未经许可不得随 Apache-2.0 发行物打包。
- 数据删除、留存和订阅终止后的处理遵循部署者实际授权；TickDeck 必须提供可执行的清理能力，但不替部署者解释合同。
- 未记录许可用途或策略发生冲突时，FR-086 默认拒绝目标动作；部署者不能用普通 UI 开关跳过。
- 外部模型、Webhook、导出和备份只能接收策略允许的最小数据；摘要、派生结果和元数据仍受相应来源许可约束。

### 8.2 Agent 与投资决策边界

- Agent 提供研究协助和模拟验证，不执行投资适当性判断，不承诺收益，不进行实盘下单。
- 用户必须能区分原始事实、确定性计算、模型解释和未知项。
- R2 确认界面必须显示对象、参数、成本、外部发送范围、组合影响、有效期和可撤销性。
- 模型生成的工具调用、扩展声明的风险和历史会话授权都不是最终权威；每次执行前由服务端重新验证 schema、数据使用策略、出站策略、风险、预算和状态版本。
- 所有第三方文本、公告、新闻、模型输出和工具结果都标记为不可信数据；其中包含的指令不得改变系统提示、工具权限或授权范围。

### 8.3 沙箱安全结果

- 沙箱脚本默认不能访问网络、文件、环境变量、进程、系统命令、原生扩展、秘密或组合存储。
- 单个脚本的崩溃、超时、资源耗尽或逃逸尝试不得影响主服务、其他运行或其他产物。
- 发布验收包含恶意脚本、资源耗尽和逃逸测试；使用某个库本身不构成安全验收。
- 默认资源档案：编译的最长实际经过时间为 10 秒；指标预览的最长实际经过时间为 5 秒，内存上限为 512 MiB，输出上限为 10 MiB；单次策略回测的最长实际经过时间为 60 秒，内存上限为 1 GiB，输出上限为 50 MiB。延长运行必须进入显式高成本路径，部署者可以收紧但不得取消硬上限。

### 8.4 成本控制

- 部署者可以设定模型、数据、回测、参数扫描和并发预算。
- 预算内 R0 任务自动执行；预计超预算的运行转为 R2。
- 第三方数据、模型和基础设施费用必须标记为外部费用，不得表述为 TickDeck 收费。

### 8.5 应用与出站安全

- 反向代理负责部署入口认证，但 TickDeck 仍负责受保护会话、请求来源、CSRF、WebSocket、可信代理和上游端口旁路防护。
- 模型、Webhook 和自定义端点使用独立凭据范围；重定向后不得把原主机凭据带到新主机。
- 私网、环回、链路本地、云元数据和解析后变化的地址默认不可作为任意自定义出站目标，除非部署者在明确风险提示下配置窄化允许项。

### 8.6 开源供应链与维护

- 受信扩展拥有的实际服务端权限必须在安装和升级前展示；来源或哈希变化视为新授权。
- v1.0 至少需要一名职责明确的项目维护者，并公开发布与安全响应责任。
- Issue 与 PR 的人工首响目标为 7 个自然日；安全报告 72 小时内确认、7 个自然日内完成初步分级。
- 当前稳定次版本及前一个次版本在后者发布后 90 天内获得严重安全修复；公共契约破坏性修改必须经过 RFC 和迁移期。

## 9. 非功能要求

### 9.1 性能与交互

参考环境为 4 vCPU、8 GB 内存、SSD、单个活跃操作者和本地缓存数据；供应商延迟单独记录。

- **NFR-001** 服务冷启动不超过 30 秒。
- **NFR-002** 应用工作台可交互时间 p95 不超过 3 秒。
- **NFR-003** 已缓存标的切换和图表呈现 p95 不超过 1 秒。
- **NFR-004** 载入 10,000 根 K 线后，常规缩放和平移保持不低于 45 FPS。
- **NFR-005** 对 10,000 个标的和 30 个已准备字段执行普通筛选，p95 不超过 5 秒。
- **NFR-006** 长时筛选、回测和 Agent 运行持续显示进度、耗时、成本并可取消；不设置脱离任务复杂度的统一完成时限。

### 9.2 可靠性与数据完整性

- **NFR-007** 相同运行清单在相同引擎版本上产生数值等价的确定性结果。
- **NFR-008** 数据源或模型故障不得破坏已保存产物；降级或换源必须显式。
- **NFR-009** 所有持久化工具和模拟订单具备幂等键与明确重试语义。
- **NFR-010** 保存、升级和迁移失败不得留下无法识别或无法恢复的半写入状态。
- **NFR-011** 备份恢复覆盖配置、研究产物、脚本、回测、模拟组合和审计记录。
- **NFR-012** 未完成 K 线、数据修订、连接器版本变化和无法完全复现的条件必须可见。

### 9.3 安全、隐私与可观测性

- **NFR-013** 所有外部输入、第三方响应和扩展配置在系统边界进行类型与内容校验。
- **NFR-014** 日志默认结构化并脱敏，不记录秘密或完整提示上下文。
- **NFR-015** 诊断包在导出前列出内容并自动脱敏。
- **NFR-016** 沙箱执行与主服务形成可验证的故障和权限隔离。
- **NFR-017** 风险确认、拒绝、超时、恢复、工具执行和模拟订单形成可查询审计记录。
- **NFR-018** 发布版本不得包含已知的严重级依赖项漏洞；发现严重问题时可以禁用受影响能力并发布修复指引。
- **NFR-019** v1.0 默认不启用遥测，不要求实例向官方服务回连。
- **NFR-020** 健康页区分 TickDeck 自身状态、数据连接器状态和模型提供商状态。

### 9.4 可访问性、语言与兼容性

- **NFR-021** 核心旅程达到 WCAG 2.2 AA，包括完整键盘操作、可见焦点、非纯颜色表达和屏幕阅读器标签。
- **NFR-022** v1.0 桌面优先；B/S 支持当前及前两个主要版本的 Chrome、Edge、Firefox 和 Safari，桌面客户端在五个固定 Release Profile 的系统 WebView 上通过同一核心旅程、可访问性和阶段表面验收；移动端不进入验收。
- **NFR-023** 界面提供简体中文和英文；安装、数据授权、安全和贡献指南提供双语版本。
- **NFR-024** 代码、公共类型、扩展清单和错误代码使用一致的英文命名。
- **NFR-025** 没有合格真实数据路径或外部模型时，演示数据与兼容测试模型仍能完成 UJ-3、UJ-4 和核心界面验收；演示数据不影响默认免费源的优先级，也不能通过真实数据资格 Gate。

### 9.5 可维护性、发布验证与兼容性

- **NFR-026** 功能模块只能依赖已声明的类型化契约，外部可观察但未承诺的行为不得写入扩展文档。
- **NFR-027** 公共扩展契约、迁移说明和契约测试与实现同时发布。
- **NFR-028** 数据连接器、模型、Agent 工具、通知和脚本 API 都能报告自身版本与兼容范围。
- **NFR-029** 关键计算和权限策略具有自动化回归基准，不依赖模型输出来判定测试通过。
- **NFR-030** alpha 调整性能或成功指标时必须保留原基线、测试环境、变更理由和新目标。
- **NFR-031** 参考能力画像的字段、许可、限频、断线、重连、复权和历史/实时一致性契约测试通过率为 100%。
- **NFR-032** 数据使用策略对未知许可、未知数据类别、未知目标动作和授权到期状态均默认拒绝，并具有属性测试。
- **NFR-033** 本地与远端模式的未授权状态修改、错误 Host/Origin、CSRF、跨站 WebSocket 和 DNS rebinding 攻击或绕过尝试的成功率必须为 0；远端模式的伪造转发头和上游端口旁路尝试的成功率也必须为 0。
- **NFR-034** 出站测试必须覆盖私网与云元数据 SSRF、DNS rebinding、危险重定向和跨主机凭据转发；攻击或绕过尝试的成功率必须为 0。
- **NFR-035** 已使用、过期、参数不匹配或状态版本过期的 Agent 授权重放成功率为 0。
- **NFR-036** 在进程崩溃、网络中断和重试注入测试下，业务副作用与追加式审计记录最终一致，重复模拟订单为 0。
- **NFR-037** 每个支持平台和发布构建必须通过同一固定版本沙箱合规套件，并保存测试环境、用例版本和结果。
- **NFR-038** 默认备份不得包含秘密值；加密秘密备份在无正确解密材料时恢复成功率为 0，恢复后必须重新验证所有 secret reference。
- **NFR-039** 官方和受信扩展发行物必须生成 SBOM、来源和哈希；缺少锁定版本或权限清单时安装默认拒绝。
- **NFR-040** v1.0 RC 前治理、支持与安全响应政策必须公开并由项目维护者完成一次演练。

## 10. 成功指标与反指标

本节的 FR 交叉引用只表示该指标直接观察的行为，不表示一次用户任务已经验证所有依赖能力。每个 FR/NFR 仍需独立验收；依赖关系由 §6.6 的切片 Gate 管理。

### 10.1 S0-V 产品 thesis Go/Stop 门

- **SM-00 Agent 增量价值：** 在 S0-V 中，至少 12 名符合 §3.1 的 alpha 用户使用一条合法真实数据路径，各自用现有工具链和受限只读 TickDeck Agent 完成至少 2 个同类真实选股任务。Go 必须同时满足：端到端任务时间中位数降低至少 30%；经盲审确认的实质错误或遗漏率降低至少 25%；至少 60% 用户在两周内主动用 Agent 完成第二个真实任务；数据许可或越权违规为 0。任一价值指标未达标则停止平台化建设，并讨论把 Agent 收窄为辅助入口或停止核心竞争力主张。直接验证 A-01 与 FR-055 的选股任务价值；工具治理和安全要求由各自 Gate 单独验收。

### 10.2 v1.0 发布门槛

- **SM-01 演示安装激活：** 至少 16/20 名测试者在 15 分钟内用演示数据打开图表并完成首次受限 Agent 查询；发布验收矩阵必须覆盖 B/S 与桌面客户端。直接验证 FR-005 的演示数据可用性和 FR-070 的两种可启动完整发行形态；模型分级、安全和诊断由独立 Gate 验收。
- **SM-01R 真实配置成本：** 至少 12 名符合 §3.1 的测试者从空白发行物开始，无维护者干预接通一个合法真实数据路径和一个模型并完成首次真实查询；成功率不低于 80%，p50 不超过 30 分钟、p95 不超过 90 分钟，配置放弃率不超过 20%；失败步骤和错误类型必须记录。直接验证 A-02、FR-001 的连接器配置、FR-065 至 FR-066 的模型配置与能力测试，以及 FR-071 的本地启动路径。
- **SM-02 研究旅程：** 12 名目标进阶投资者中至少 80% 无需协助完成 UJ-1；真实数据任务必须使用通过 SM-10 的连接器。验证 FR-008 至 FR-028、FR-052 至 FR-064、FR-084 至 FR-094。

## 12. 开放问题与已解决记录

1. **OQ-01 演示数据来源与许可 [RESOLVED 2026-08-28]。** 官方 demo 只使用固定版本、固定种子的确定性合成数据，不打包第三方真实历史行情；覆盖 A/港股日线/分钟线、停牌、涨跌停、T+1、港股手数、多币种、公司行动及缺失/陈旧/部分状态，明确标记 `demo/non-current`，永不计入 SM-10 或真实数据 v1.0 Gate。
2. **OQ-02 Alpha 用户招募与基线任务 [RESOLVED 2026-08-28]。** 协议固定为至少 12 名符合 §3.1 的用户且样本整体覆盖 A/港股合法数据使用者；每人完成至少两次同类真实选股任务，并分别使用现有工具链与 TickDeck；实验前冻结任务、oracle、盲审规则和现有工具链基线；记录任务时间、实质错误/遗漏、人工修正、证据核查成本和两周内复用。样本、任务、数据权利或冻结条件不满足时实验无效，不得进入 S2。协议关闭不代表已招募或 SM-00 已通过。
3. **OQ-03 首批免费 A/港股连接器。** 负责人：项目维护者；S1 前为 A 股和港股分别选择并验证合法免费数据路径，按 §6.4 核对字段、时效、历史、稳定性、许可用途和健康；免费路径不合格时收窄相应市场或保持 beta，不得静默改用商用源。部署者仍可主动配置经同等资格验证的商用连接器。
4. **OQ-04 公共发布法律文本。** 负责人：项目维护者；在公开 beta 前核对数据许可、第三方内容、免责声明和隐私说明。本文档不构成法律意见。
5. **OQ-05 性能参考环境复核。** 负责人：工程与 QA；首轮 alpha 基准后保留原基线并决定是否调整 NFR-001 至 NFR-006。
6. **OQ-06 沙箱支持平台与粗粒度隔离。** 负责人：架构与安全；S0 开工前选择支持平台、隔离边界和终止机制，并证明能够执行 FR-095 与 NFR-037。
7. **OQ-07 备份维护者 [RETIRED 2026-08-28]。** 用户确认不要求强制备份维护者；ID 不复用。至少一名明确项目维护者及现有发布/安全响应演练要求继续有效。
